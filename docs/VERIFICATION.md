# Проверка MVP

Проверено локально 4 октября 2026 года на macOS, Node.js 22.22.3 и Docker Desktop. Эти результаты относятся к созданной версии MVP.

| Проверка                    | Результат                                                     |
| --------------------------- | ------------------------------------------------------------- |
| `pnpm lint`                 | Успешно, без предупреждений                                   |
| `pnpm typecheck`            | Успешно, strict TypeScript                                    |
| `pnpm format:check`         | Успешно                                                       |
| `pnpm test`                 | 26 тестов прошли                                              |
| `pnpm test:integration`     | 13 тестов прошли на отдельной PostgreSQL-базе `fieldops_test` |
| `pnpm exec prisma validate` | Схема корректна                                               |
| `pnpm db:migrate`           | Начальная миграция применена                                  |
| `pnpm db:seed`              | Демоданные созданы, повторный запуск сохраняет записи         |
| `pnpm build`                | Production-сборка прошла                                      |
| `docker compose config -q`  | Конфигурация корректна                                        |
| `docker compose build`      | Образы `app` и `init` собраны                                 |
| Docker `init`               | Миграции и seed выполнены, код выхода 0                       |
| Docker `db`                 | PostgreSQL 17 запущен и healthy                               |
| Docker `app`                | Standalone-приложение работает на `127.0.0.1:3000`            |
| `pnpm test:smoke`           | Прошёл на локальной Node-сборке и затем на Docker-приложении  |

Интеграционные тесты проверяют создание и назначение заявки, ограничения ролей, связь устройства с объектом, единственный активный выезд, поездку и прибытие, принадлежность шагов шаблону, завершение диагностики, запрет её дальнейшего редактирования, откат некорректного решения, создание истории ремонта и закрытие заявки.

HTTP-проверка включает анонимный доступ, вход Auth.js, 15 страниц, фильтр инженера, недоступный чужой инцидент, запрет изменений для наблюдателя, проверку `Origin` и поиск по IP. Бизнес-сценарий проверяется сервисами на PostgreSQL, а не полностью автоматизированными кликами по интерфейсу.

В браузере проверены вход демо-инженера, dashboard, загрузка MapLibre и карточка инцидента. На ширинах 1280 и 390 px карточка не создаёт горизонтального переполнения страницы. Снимки находятся в `docs/screenshots/`.

После повторного seed в основной демо-базе осталось 5 пользователей, 16 объектов, 144 устройства, 20 инцидентов и 6 выездов. Тесты использовали отдельную базу и удалили только свои временные записи.

Не проверялись публичное развёртывание, реальные интеграции с оборудованием и полный набор браузеров/мобильных устройств. Мониторинг и оповещения используют вымышленные состояния; симулятор и AI-провайдер входят в roadmap.

Добавлены 23 unit-теста параметров, ссылок и фильтров, 7 тестов контракта API и 8 PostgreSQL-тестов пагинации. Тесты API используют подмену сессии и запросов: они проверяют HTTP-контракт, но не подтверждают работу PostgreSQL. Интеграционные тесты подготовлены для отдельной базы `_test`; они проверяют 210 инцидентов и 505 устройств, включая записи за прежними пределами и ограничения инженера.

Turbopack не смог открыть служебный локальный порт при обработке CSS: `binding to a port: Operation not permitted (os error 1)`. Повторный запуск с расширенным разрешением получил ту же ошибку. Поддерживаемый Next.js режим Webpack успешно собрал приложение; настройки стандартной сборки проекта сохранены.

На этом этапе не выполнялись миграции, seed, публикация и браузерная проверка. Схема базы и зависимости не менялись. Предыдущие результаты проверки MVP выше относятся к версии от 4 октября и не заменяют текущую проверку интеграций.

## Выбор оборудования — 8 октября 2026 года

Форма нового инцидента загружает лёгкий список устройств выбранного объекта через отдельный API. Общий лимит в 500 устройств больше не скрывает варианты формы; списанные устройства исключены. Добавлены инвентарные номера, IP, состояния загрузки, пустого списка и ошибки, повторная попытка и сброс выбора при смене объекта.

| -------------------------------- | ----------------------------------------------------- |
| `pnpm lint`                      | Успешно, без предупреждений                           |
| `pnpm typecheck`                 | Успешно                                               |

| `pnpm test`                      | 60 тестов прошли                                      |
| `pnpm test:integration`          | 24 теста прошли на отдельной базе `fieldops_test`     |
| `pnpm test:smoke`                | Успешно на локальной production-сборке                |
| `pnpm exec next build --webpack` | Production-сборка прошла                              |

Четыре новых теста API проверяют контракт лёгкого списка, приоритет объекта из пути над параметрами запроса, ошибки объекта и необходимость входа. Три новых PostgreSQL-теста подтверждают выдачу всех 504 действующих устройств из набора в 505 записей, исключение `RETIRED`, пустой объект и ошибки неизвестного/отключённого объекта. В ответ входят только `id`, `name`, `assetTag`, `ipAddress`.

HTTP-проверка дополнена входом диспетчера, страницей создания инцидента, сравнением вариантов с оборудованием конкретного объекта, защитой анонимного доступа и заголовком `no-store`. Миграции тестовой базы актуальны; основная демо-база не менялась. При завершении тестов удалены только созданные ими записи. В PostgreSQL-тестах остаётся предупреждение `pg` о параллельных `client.query()`; тесты завершились успешно.

Ошибка стандартной сборки соответствует описанному выше ограничению среды: `binding to a port: Operation not permitted (os error 1)`. Проверка выполнена через поддерживаемый режим Webpack. Настройки сборки, зависимости и схема данных не изменены. Поведение формы при кликах, смене объекта и сетевой ошибке в браузере на этом этапе не проверялось.

## Качество кода — 19 октября 2026 года

Выполнены пять самостоятельных улучшений:

- Координаты объекта принимают числа и непустые числовые строки из формы. Пустые строки, `null`, логические значения, массивы и нечисловые значения отклоняются; нулевые координаты и прежние ограничения карты сохранены.
- Фильтр даты инцидентов игнорирует несуществующие календарные даты вместо их переноса на другой день. Корректные даты, включая високосные дни, используют полуоткрытый интервал суток по Москве.
- API отклоняет лишние сегменты пути и имена действий из прототипа объекта до вызова запросов и сервисов. Допустимые GET, POST и PATCH сохраняют прежний контракт.
- Шесть Zod-схем enum используют сгенерированные значения Prisma. TypeScript проверяет полноту локализованных справочников; список активных статусов больше не требует приведения типов.
- `nextStatuses()` возвращает копию списка переходов, поэтому вызывающий код не может изменить правила инцидента. Таблицы переходов инцидентов и выездов имеют типы только для чтения; таблица выездов больше не создаётся при каждом вызове проверки.
